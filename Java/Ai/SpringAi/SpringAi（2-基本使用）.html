SpringAi（2-基本使用）

爱编程的小生2025/12/2大约 10 分钟JavaSpringAiAi

版本、依赖及配置

本文示例以 Spring AI 1.1.2 为基准，对应的 Spring Boot 版本使用 3.5.8，JDK 使用 17：

JDK 17 + Spring Boot 3.5.8 + Spring AI 1.1.2

Spring AI、Spring Boot 和 JDK 需要使用兼容的版本组合。升级其中一个版本时，应一起检查另外两个版本以及示例代码是否仍然适用。

Maven 依赖

使用 BOM 统一管理 Spring AI 模块的版本，Starter 本身不再单独声明版本：

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-dependencies</artifactId>
            <version>3.5.8</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
        <dependency>
            <groupId>org.springframework.ai</groupId>
            <artifactId>spring-ai-bom</artifactId>
            <version>1.1.2</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>

    <dependency>
        <groupId>org.springframework.ai</groupId>
        <artifactId>spring-ai-starter-model-openai</artifactId>
    </dependency>
</dependencies>

spring-ai-starter-model-openai 提供 OpenAI 模型的 Spring Boot 自动配置，也可以连接遵循 OpenAI 接口规范的其他模型服务。

模型配置

下面以阿里云百炼的 OpenAI 兼容接口为例：

spring:
  ai:
    openai:
      # 模型服务的基础访问地址。
      base-url: https://dashscope.aliyuncs.com/compatible-mode
      # API Key 是模型服务商签发的访问凭证，用来验证当前应用是否有权调用模型。
      api-key: 
      chat:
        options:
          # 要调用的聊天模型名称，必须是当前服务商和账号实际提供的模型。
          model: qwen3-max
          # 控制输出的随机性：值越低，回答越稳定；值越高，回答越有变化。
          temperature: 0.75

消息、Prompt 与响应

消息角色

和人进行一次对话时，消息通常会带有不同的角色。角色的作用是让模型知道“这句话是谁说的，以及它在对话中承担什么作用”。Spring AI 通过不同的 Message 类型表达这些角色。

Spring AI 使用 MessageType 表示消息角色：

public enum MessageType {
    USER("user"),
    ASSISTANT("assistant"),
    SYSTEM("system"),
    TOOL("tool");
}

System：系统消息

系统消息用于设置模型的背景、身份、行为规则和输出要求。例如：

你是一名 Java 技术助手，只回答 Java 和 Spring 相关问题，回答要简洁。

对应的 Spring AI 类型是 SystemMessage。系统消息通常由应用程序设置，而不是由用户直接控制。

User：用户消息

用户消息是用户提出的问题、要求或补充信息，例如：

什么是 Spring AI？

对应的类型是 UserMessage。一次最简单的模型调用，通常就是把用户输入包装成一条 UserMessage。

Assistant：助手消息

助手消息表示模型之前生成的回复，例如：

Spring AI 是一个用于构建 AI 应用的 Spring 框架。

对应的类型是 AssistantMessage。在多轮对话中，应用需要把之前的用户消息和助手消息一起传回模型，模型才能获得历史上下文。

Tool：工具消息

工具消息用于表示工具调用过程中的信息。模型可能先生成一个工具调用请求，应用执行工具后，再把工具执行结果作为工具消息传回模型，让模型继续生成最终回答。

在 Spring AI 中，工具执行结果通常使用 ToolResponseMessage 表示。工具消息的作用是传递工具结果，不代表应用已经完成权限校验；真正的权限控制仍然由应用程序负责。

Prompt 与 ChatResponse

理解消息角色后，再看一次完整的模型调用：

SystemMessage + UserMessage + 历史消息
                ↓
              Prompt
                ↓
            ChatModel
                ↓
          ChatResponse

Prompt：发送给模型的请求

Prompt 是一次发送给模型的请求，它可以包含一条或多条 Message，也可以携带模型参数。

只有一条用户消息时：

Prompt prompt = new Prompt(
        new UserMessage("Spring AI 是什么？"));

包含系统消息和历史对话时：

Prompt prompt = new Prompt(List.of(
        new SystemMessage("你是一名 Java 助手"),
        new UserMessage("什么是 Spring Boot？"),
        new AssistantMessage("Spring Boot 用于简化 Spring 应用开发。"),
        new UserMessage("它和 Spring AI 有什么关系？")
));

模型本身通常不会自动记住上一次请求。要实现连续对话，应用需要在后续请求中重新提交历史消息；下一篇“会话记忆”会介绍如何自动管理这些历史消息。

ChatResponse：模型返回的结果

如果只需要文本，可以使用 ChatModel 提供的字符串快捷调用。如果需要读取完整响应，则使用 ChatResponse：

ChatResponse response = chatModel.call(prompt);
String text = response.getResult().getOutput().getText();

ChatResponse 的核心内容是模型生成的文本，同时还可能包含模型名称、结束原因和 Token 使用量等元数据。具体能读取哪些元数据，取决于模型服务商和当前调用方式。

ChatModel

ChatModel 是 Spring AI 对聊天模型的统一抽象。它提供同步调用和流式调用两种方式，也可以直接接收字符串、Prompt 等请求对象。

常用方法可以先这样理解：

方法参数返回值适用场景
call(String)一段文本String快速获得文本结果
call(Prompt)结构化 PromptChatResponse需要读取完整响应信息
stream(String)一段文本Flux<String>逐段读取文本
stream(Prompt)结构化 PromptFlux<ChatResponse>逐段读取响应及元数据

call 会等待模型完成后返回，stream 会在模型生成过程中持续返回结果片段。

同步调用

@RestController
public class ChatModelController {

    @Resource
    private ChatModel chatModel;
 
    @RequestMapping("/chat")
    public String chat(@RequestParam("msg") String msg) {
        return chatModel.call(msg);
    }
}

基于 call() 的调用属于同步调用，需要模型完成响应后才能返回结果。使用字符串参数时，Spring AI 会在内部把文本转换成用户消息；需要控制消息角色或模型参数时，应使用 Prompt。

流式调用

同步调用需要等待模型生成完整结果后页面才能看到内容。流式调用则会在模型生成过程中持续返回文本片段，适合需要逐步展示结果的场景。

stream() 返回 Reactor 的 Flux，调用方可以逐段消费模型结果。

@RestController
public class ChatModelController {

    @Resource
    private ChatModel chatModel;
 
    // 注意看返回值，是Flux<String>，也就是流式结果，另外需要设定响应类型和编码，不然前端会乱码
    @RequestMapping(value = "/stream", produces = "text/html;charset=utf-8")
    public Flux<String> stream(@RequestParam("msg") String msg) {
        return chatModel.stream(msg);
    }
}

Prompt、Message 与模板

当请求只包含一段用户文本时，直接使用 call(String) 或 stream(String) 即可；当请求包含系统消息、历史消息或模板变量时，应先构造 Prompt。

使用 Prompt

Prompt 可以把一条或多条消息组合成一次模型请求：

@GetMapping("/call-with-prompt")
public String callWithPrompt(@RequestParam("msg") String msg) {
    Prompt prompt = new Prompt(new UserMessage(msg));
    ChatResponse response = chatModel.call(prompt);
    return response.getResult().getOutput().getText();
}

使用 Message 构造 Prompt

当需要明确指定消息角色时，先创建具体的 Message，再放入 Prompt：

Message userMessage = new UserMessage("Spring AI 是什么？");
Prompt prompt = new Prompt(userMessage);

ChatResponse response = chatModel.call(prompt);
String text = response.getResult().getOutput().getText();

多轮对话可以把系统消息、历史消息和当前用户消息放在同一个 Prompt 中：

Prompt prompt = new Prompt(List.of(
        new SystemMessage("你是一名 Java 助手"),
        new UserMessage("什么是 Spring Boot？"),
        new AssistantMessage("Spring Boot 用于简化 Spring 应用开发。"),
        new UserMessage("它和 Spring AI 有什么关系？")
));

使用 PromptTemplate

PromptTemplate 用于创建带变量的消息模板。模板中的 {question} 是占位符，调用 createMessage() 时传入实际值：

PromptTemplate template = new PromptTemplate(
        "针对用户提出的问题：{question}，请尽量简洁地回答。");
Message userMessage = template.createMessage(
        Map.of("question", "Spring AI 是什么？"));

ChatResponse response = chatModel.call(new Prompt(userMessage));
String text = response.getResult().getOutput().getText();

PromptTemplate 只负责根据模板生成消息，真正发送请求仍然由 ChatModel 或 ChatClient 完成。

ChatClient

ChatClient 建立在 ChatModel 之上，使用 fluent API 组装用户消息、系统消息、模板和 Advisor。相比直接调用 ChatModel，它更适合在业务代码中使用。

ChatClient 不会替换底层的 ChatModel，它只是提供了更方便的请求构建方式。prompt() 用于开始构建请求，user() 和 system() 用于添加消息，call() 执行同步调用，stream() 执行流式调用。

@Configuration
public class ChatClientConfig {

    @Bean
    public ChatClient chatClient(ChatModel chatModel) {
        return ChatClient.builder(chatModel)
                .build();
    }
}
@RestController
public class ChatClientController {

    @Resource
    private ChatClient chatClient;

    /**
     * prompt()参数使用 String
     */
    @RequestMapping("/chat")
    public String chat(@RequestParam("msg") String msg) {
        return chatClient.prompt(msg).call().content();
    }

    /**
     * prompt()参数使用 Prompt
     */
    @RequestMapping("/chatV2")
    public String chatV2(@RequestParam("msg") String msg) {
        Prompt prompt = new Prompt(new UserMessage(msg));
        return chatClient.prompt(prompt).call().content();
    }

    /**
     * 不带参数的 prompt()
     */
    @RequestMapping("/chatV3")
    public String chatV3(@RequestParam("msg") String msg) {
        return chatClient.prompt().user(msg).call().content();
    }

    /**
     * 使用提示词模版
     */
    @RequestMapping("/chatV4")
    public String chatV4(@RequestParam("msg") String msg) {
        // 可以通过 PromptTemplate 设置，也可以通过 user()或者 system()方法设置。
        return chatClient.prompt()
                .user(item -> item.text("针对用户的问题：{question}，尽量回答的简略")
                        .param("question", msg))
                .call().content();
    }
    
    @RequestMapping("/chatStream")
    public Flux<String> chatStream(@RequestParam("msg") String msg) {
        return chatClient.prompt(msg).stream().content();
    }
}

同步调用常用 content() 读取最终文本；如果需要完整的 ChatResponse，可以使用 chatResponse()。流式调用可以使用 stream().content() 获取文本片段，也可以使用 stream().chatResponse() 获取带元数据的响应片段。

默认情况下，模板变量由 {} 语法标识。如果您打算在提示中包含 JSON，您可能需要使用不同的语法来避免与 JSON 语法冲突。例如，您可以使用 < 和 > 分隔符。

String answer = ChatClient.create(chatModel)
    .prompt()
    .user(u -> u.text("composed by <composer>")
            .param("composer", "John Williams"))
    .templateRenderer(StTemplateRenderer.builder()
                      .startDelimiterToken('<')
                      .endDelimiterToken('>')
                      .build())
    .call()
    .content();

System Prompt

System Prompt 用于告诉模型应该以什么身份、遵循什么规则以及采用什么输出方式。例如：

你是一名 Java 技术助手，只回答 Java 和 Spring 相关问题，回答要简洁。

ChatClient 支持设置默认 System Prompt，也支持在单次请求中设置 System Prompt。

默认 System Prompt

默认 System Prompt 会应用到使用该 ChatClient 的每一次请求：

@Bean
public ChatClient chatClient(ChatModel chatModel) {
    return ChatClient.builder(chatModel)
            .defaultSystem("你是一名 Java 技术助手，只回答 Java 和 Spring 相关问题。")
            .build();
}

请求级 System Prompt

请求级 System Prompt 只对当前请求生效，可以使用模板参数：

String answer = chatClient.prompt()
        .system(system -> system
                .text("你是{name}，回答要简洁。")
                .param("name", "小板"))
        .user("你是谁？")
        .call()
        .content();

默认 System Prompt 适合放置稳定的角色和规则，请求级 System Prompt 适合放置本次请求才需要的背景信息。System Prompt 只是发送给模型的指令，不能代替应用的权限校验。

Advisor

Advisor 是 ChatClient 调用链中的增强组件，可以在请求发送前补充或修改 Prompt，也可以在模型响应返回后进行处理。

常见的 Advisor 包括：

  • SimpleLoggerAdvisor：记录请求和响应，便于调试。
  • MessageChatMemoryAdvisor：把历史消息加入当前 Prompt。
  • QuestionAnswerAdvisor：根据向量库检索结果补充上下文。
  • SafeGuardAdvisor：根据规则拦截不允许的输入或输出。

Advisor 的执行顺序会影响最终结果。多个 Advisor 一起使用时，应根据它们对请求的修改关系安排顺序。

Advisor 既可以在创建 ChatClient 时作为默认配置，也可以只对某一次请求启用：

String answer = chatClient.prompt()
        .user("请回答这个问题")
        .advisors(new SimpleLoggerAdvisor())
        .call()
        .content();

添加日志 Advisor

@Bean
public ChatClient chatClient(ChatModel chatModel) {
    return ChatClient.builder(chatModel)
            .defaultAdvisors(new SimpleLoggerAdvisor())
            .build();
}

日志级别配置：

logging:
  level:
    org.springframework.ai.chat.client.advisor: DEBUG

日志可能包含用户输入、System Prompt 和模型输出，调试时应注意敏感信息。

添加安全 Advisor

@Bean
public SafeGuardAdvisor safeGuardAdvisor() {
    return SafeGuardAdvisor.builder()
            // 设置敏感词列表，用于过滤用户输入和AI输出中的不当内容
            .sensitiveWords(Arrays.asList("黄色"))
            // 当检测到敏感内容时返回的提示信息
            .failureResponse("请注意措辞")
            .build();
}

@Bean
public ChatClient chatClient(ChatModel chatModel,
                             SafeGuardAdvisor safeGuardAdvisor) {
    return ChatClient.builder(chatModel)
            .defaultAdvisors(
                    new SimpleLoggerAdvisor(),
                    safeGuardAdvisor)
            .build();
}

安全 Advisor 只能提供应用层规则校验，不能代替模型服务商的安全策略和业务权限控制。

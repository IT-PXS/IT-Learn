Admin 调度中心配置

导入 sql 脚本

  1. xxl_job_group：执行器信息表

  • 描述：维护“执行器”的配置信息。

  • 作用：对应 Web 页面中的“执行器管理”。它定义了任务分组（app_name），调度中心通过这个名称来寻找注册上来的执行器机器。

  • 关键点：包含注册方式（自动注册/手动录入）和具体的机器地址列表（如果是手动录入）。

  1. xxl_job_registry：执行器注册表

  • 描述：维护在线的执行器节点信息（动态变动）。

  • 作用：执行器（Client 端）启动后会周期性（默认为 30 秒）向调度中心发送心跳，调度中心将存活的机器地址（IP: Port）更新到此表。

  • 关键点：调度中心调度任务时，会根据 xxl_job_group 找到对应的 app_name，再查此表获取实际的物理机器地址进行路由。

  1. xxl_job_info：任务详情表（核心）

  • 描述：保存 XXL-JOB 调度任务的所有配置信息。

  • 作用：对应 Web 页面中的“任务管理”列表。

  • 关键点：包含 Cron 表达式、调度过期策略、阻塞处理策略、任务执行器（JobHandler）、路由策略、分片参数、超时时间、失败重试次数等核心参数。

  1. xxl_job_log：调度日志表（数据量最大）

  • 描述：记录每一次任务触发的完整生命周期。

  • 作用：对应 Web 页面中的“调度日志”。

  • 关键点：包含两个阶段的信息：

    • 调度阶段：调度时间、调度结果（成功/失败）、调度备注。

    • 执行阶段：执行时间、执行结果（成功/失败）、执行备注、以及执行器地址。

注意：此表数据量增长极快，生产环境通常需要配置定期清理策略。
5. xxl_job_log_report：调度报表（统计表）

  • 描述：专门用于存储按天维度的调度统计数据。

  • 作用：服务于调度中心首页的“日期分布图”和“运行报表”。

  • 关键点：调度中心会异步统计 xxl_job_log 的数据，汇总后写入此表。

  1. xxl_job_logglue：任务 GLUE 日志

  • 描述：记录 GLUE 模式（在线编辑代码）下的代码变更历史。

  • 作用：支持 GLUE 代码的版本回溯功能。

  • 关键点：当用户在 Web IDE 中修改 Java/Shell/Python 代码并保存时，旧版本代码会存入此表，方便回滚。

  1. xxl_job_lock：分布式锁表

  • 描述：XXL-JOB 调度中心集群高可用（HA）的核心依赖。

  • 作用：确保在调度中心集群部署时，同一时刻只有一个调度节点能触发特定的调度逻辑，避免重复调度。

  • 关键点：利用数据库的悲观锁（for update）机制实现。

  1. xxl_job_user：系统用户表

  • 描述：维护调度中心的操作用户。

  • 作用：管理登录账号、密码（加密）以及权限（管理员/普通用户）。

  • 关键点：普通用户通常需要绑定特定的 xxl_job_group（执行器），实现权限隔离。

@Configuration
public class XxlJobConfig {
    private static final Logger logger = LoggerFactory.getLogger(XxlJobConfig.class);

    @Value("${xxl.job.admin.addresses}")
    private String adminAddresses;

    @Value("${xxl.job.admin.accessToken}")
    private String accessToken;

    @Value("${xxl.job.admin.timeout}")
    private int timeout;

    @Value("${xxl.job.executor.enabled}")
    private Boolean enabled;

    @Value("${xxl.job.executor.appname}")
    private String appname;

    @Value("${xxl.job.executor.address}")
    private String address;

    @Value("${xxl.job.executor.ip}")
    private String ip;

    @Value("${xxl.job.executor.port}")
    private int port;

    @Value("${xxl.job.executor.logpath}")
    private String logPath;

    @Value("${xxl.job.executor.logretentiondays}")
    private int logRetentionDays;

    @Value("${xxl.job.executor.excludedpackage}")
    private String excludedPackage;

    @Bean
    public XxlJobSpringExecutor xxlJobExecutor() {
        logger.info(">>>>>>>>>>> xxl-job config init.");
        XxlJobSpringExecutor xxlJobSpringExecutor = new XxlJobSpringExecutor();
        xxlJobSpringExecutor.setAdminAddresses(adminAddresses);
        xxlJobSpringExecutor.setAccessToken(accessToken);
        xxlJobSpringExecutor.setTimeout(timeout);
        xxlJobSpringExecutor.setEnabled(enabled);
        xxlJobSpringExecutor.setAppname(appname);
        xxlJobSpringExecutor.setAddress(address);
        xxlJobSpringExecutor.setIp(ip);
        xxlJobSpringExecutor.setPort(port);
        xxlJobSpringExecutor.setLogPath(logPath);
        xxlJobSpringExecutor.setLogRetentionDays(logRetentionDays);
        xxlJobSpringExecutor.setExcludedPackage(excludedPackage);
        return xxlJobSpringExecutor;
    }

    /**
     * 针对多网卡、容器内部署等情况，可借助 "spring-cloud-commons" 提供的 "InetUtils" 组件灵活定制注册IP；
     *
     *      1、引入依赖：
     *          <dependency>
     *             <groupId>org.springframework.cloud</groupId>
     *             <artifactId>spring-cloud-commons</artifactId>
     *             <version>${version}</version>
     *         </dependency>
     *
     *      2、配置文件，或者容器启动变量
     *          spring.cloud.inetutils.preferred-networks: 'xxx.xxx.xxx.'
     *
     *      3、获取IP
     *          String ip_ = inetUtils.findFirstNonLoopbackHostInfo().getIpAddress();
     */
}

注意：

  1. 在 xxl-job 中，获取 IP 是通过 ipUtils 类中的 getIp()获取的：首先获取的是 localhost，如果在本地没取到 IP，那么就会去获取所有网卡接口，依次遍历（localAddrs [] 总是获取的第一个，如果当前网卡存在 2 个，第一个 eth0 状态不可用，第二个 eth1 状态可用，那么他总是会取到不可用 IP，导致服务出现问题）

  2. InetUtils 中的 findFirstNonLoopbackAddress()是先去获取了网卡接口，再遍历并且依次判断当前地址是否是开启的，然后判断了当前网卡接口是不是被配置了可忽略，然后获取到地址之后 address instanceof Inet4Address && ! address.isLoopbackAddress() && ! this.ignoreAddress(address)，如果符合条件赋值给 result，后续判断如果 result 不为 null，则直接返回，如果为空，再去 InetAddress.getLocalHost()

/**
 * 开发步骤：
 * 1、任务开发：在 Spring Bean 实例中，开发 Job 方法；
 * 2、注解配置：为 Job 方法添加注解 "@XxlJob(value =" 自定义 jobhandler 名称 ", init = " JobHandler 初始化方法 ", destroy = " JobHandler 销毁方法 ")"，注解 value 值对应的是调度中心新建任务的 JobHandler 属性的值。
 * 3、执行日志：需要通过 "XxlJobHelper.log" 打印执行日志；
 * 4、任务结果：默认任务结果为 "成功" 状态，不需要主动设置；如有诉求，比如设置任务结果为失败，可以通过 "XxlJobHelper.handleFail/handleSuccess" 自主设置任务结果；
 */
@Component
@Slf4j
public class TestHandler {

    @XxlJob(value = "TestHandler")
    public boolean demoJobHandler(){
        XxlJobHelper.log("XXL-JOB, TestHandler.");
        log.info("定时任务开始 job start");
        long startTime  = System.currentTimeMillis();
        System.out.println("hello world");
        long endTime  = System.currentTimeMillis();
        log.info("定时任务开始 job end, cost: {} ms"+(endTime - startTime));
        return XxlJobHelper.handleSuccess();
    }
}

添加 GLUE （Java）任务

添加子任务

XXL-JOB 中有自带的子任务编排功能，支持子任务依赖，当父任务执行结束且执行成功后将会主动出发一次子任务的执行，多个子任务使用逗号分隔

  1. 优点：

适合连续，连贯的业务场景，框架自带任务编排，使用简单，只需要通过调度中心页面配置即可实现

  1. 缺点：

连续任务的数据不能直接进行传递，不像 JAVA 中 CompletableFuture 可以将上一个任务的执行结果传递到后续使用，可以就需要将每个任务的处理数据，存储到第三方存储中，比如 Mysql，Redis 等

分片广播任务

使用案例 1

定时任务逻辑里，根据获取到的分片参数、执行任务节点数量，决策当前节点是否需要执行，分片查询数据并处理：

  1. 如果分片序号 > (执行任务节点数量 - 1)，则当前节点不执行任务，直接返回；

  2. 否则，取【分片序号】和 【执行任务节点数量】作为分片参数，查询数据并处理。

@XxlJob("demoJobHandler")
public void execute() {
    // 获取任务执行参数
    String param = XxlJobHelper.getJobParam();
    if (StringUtils.isBlank(param)) {
        XxlJobHelper.log("任务参数为空");
        XxlJobHelper.handleFail();
        return;
    }

    // 执行任务节点数量
    int executeNodeNum = Integer.valueOf(param);
    // 分片序号
    int shardIndex = XxlJobHelper.getShardIndex();
    // 分片总数
    int shardTotal = XxlJobHelper.getShardTotal();
    if (executeNodeNum <= 0 || executeNodeNum > shardTotal) {
        XxlJobHelper.log("执行任务节点数量取值范围[1,节点总数]");
        XxlJobHelper.handleFail();
        return;
    }

    if (shardIndex > (executeNodeNum - 1)) {
        XxlJobHelper.log("当前分片 {} 无需执行", shardIndex);
        XxlJobHelper.handleSuccess();
        return;
    }
    // 业务逻辑处理
    // ......
    XxlJobHelper.handleSuccess();
}

使用案例 2

处理数据时，每个节点实例获取当前的分片序号，分片计算自己需要处理的数据范围

@Slf4j
@Component
@RequiredArgsConstructor
public class ProductLearnToEsJob {

    private static final Integer BATCH_SIZE = 1000;
    private static final DateTimeFormatter DATE_TIME_FORMATTER = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");

    private final MongoTemplate mongoTemplate;
    private final ProductLearnEsService productLearnEsService;

    @XxlJob("productLearnToEsJob")
    public void exec() throws Exception {
        log.info("ProductLearnToEsJob start");
        Criteria criteria = Criteria.where(BaseEntity.DELETED).is(0L);
        String param = XxlJobHelper.getJobParam();
        if (StringUtils.isNotBlank(param)) {
            ProductLearnStatusSyncDTO syncDTO = JSON.parseObject(param, ProductLearnStatusSyncDTO.class);
            if (Objects.nonNull(syncDTO.getStartTime()) && Objects.nonNull(syncDTO.getEndTime())) {
                LocalDateTime startTime = LocalDateTime.parse(syncDTO.getStartTime(), DATE_TIME_FORMATTER);
                LocalDateTime endTime = LocalDateTime.parse(syncDTO.getEndTime(), DATE_TIME_FORMATTER);
                criteria.and(AgentShopUnLearningProduct.LAST_UPDATED_AT).gte(startTime).lte(endTime);
            }
            if (Objects.nonNull(syncDTO.getGroupId())) {
                criteria.and(AgentShopUnLearningProduct.GROUP_ID).is(syncDTO.getGroupId());
            }
        }
        long count = mongoTemplate.count(new Query(criteria), AgentShopLearningProduct.class);
        if (count <= 0) {
            log.info("ProductLearnToEsJob data empty, end");
            return;
        }
        // 分片参数
        int index = XxlJobHelper.getShardIndex();
        int total = XxlJobHelper.getShardTotal();

        log.info("ProductLearnToEsJob total count:{}, sharding index:{}, total:{}", count, index, total);
        long sum = (long) Math.ceil((double) count / total);
        long start = sum * index;
        long end = Math.min(sum * (index + 1), count);
        log.info("ProductLearnToEsJob sum:{}, index:{}, start:{}, end:{}", count, index, start, end);

        // 整个分片只需执行一次 skip
        Query startQuery = new Query(criteria)
                .with(Sort.by(Sort.Direction.ASC, "_id"))
                .skip(start)
                .limit(1);
        startQuery.fields().include("_id");
        AgentShopLearningProduct firstItem = mongoTemplate.findOne(startQuery, AgentShopLearningProduct.class);
        if (firstItem == null) {
            return;
        }
        ObjectId lastId = firstItem.getId();
        long processedInShard = 0;
        long totalToProcess = end - start;
        // 【核心循环】使用 _id 锚点进行滚动查询
        while (processedInShard < totalToProcess) {
            // 计算本批次实际需要读取的数量，防止超出分片边界
            int currentBatchSize = (int) Math.min(BATCH_SIZE, totalToProcess - processedInShard);
            if (currentBatchSize <= 0) {
                break;
            }

            Query query = new Query(criteria);
            // 使用 gt 或 gte。第一次循环用 gte 包含起始 ID，后续用 gt
            if (processedInShard == 0) {
                query.addCriteria(Criteria.where("_id").gte(lastId));
            } else {
                query.addCriteria(Criteria.where("_id").gt(lastId));
            }
            query.limit(currentBatchSize);
            query.with(Sort.by(Sort.Direction.ASC, "_id")); // 必须固定排序
            query.fields().include(AgentShopLearningProduct.THIRD_SHOP_ID,
                    AgentShopLearningProduct.SPU_ID,
                    BaseEntity.DELETED);

            List<AgentShopLearningProduct> list = mongoTemplate.find(query, AgentShopLearningProduct.class);
            if (CollectionUtils.isEmpty(list)) {
                break;
            }
            // 执行同步业务
            productLearnEsService.syncLearnStatusToEs(list);
            // 更新锚点 ID 为本批次最后一条数据的 ID
            lastId = list.get(list.size() - 1).getId();
            processedInShard += list.size();
            log.info("Shard index:{}, processed:{}/{}", index, processedInShard, totalToProcess);
        }
    }
}

编写与验证自定义 Skill

爱编程的小生2026/10/11大约 2 分钟

编写与验证自定义 Skill

对应技能：writing-skills。适合把反复出现、已有成功经验的工作方式沉淀成可复用技能，不是把一次聊天记录直接保存为 SKILL.md。

核心方法

技能编写也采用对照验证：先观察没有新技能时的失败行为，再写最小指导，最后在同类与变体场景中验证是否改善。

阶段例子：防止导出功能遗漏权限检查
无技能基线给 agent 导出需求，观察是否遗漏权限条件
最小技能明确适用场景、权限输入、验证步骤和输出要求
有技能验证重跑同类场景，检查行为是否按预期改变
变体与压力场景数据规模变化、时间压力、模糊权限要求等

如果无技能基线已经正确，先判断是否真的需要新增技能，避免不断增加重复规则。

可复制指令

我想用 writing-skills 把 <反复出现的工作方法> 做成个人技能。
适用场景：<场景>。希望避免的问题：<具体错误>。
先设计无技能与有技能的对照场景，记录基线行为。
确认存在需要解决的问题后，再编写最小 SKILL.md 和必要辅助材料。
描述中写清什么时候使用；正文给出步骤、边界、验证和输出要求。
用子 agent 验证典型、边界及易误用场景，记录结果。
先把草稿和测试报告放在 <工作区内目录>，不要直接覆盖已有技能。
不提交、不推送、不安装到个人技能目录。

预期结果

除了技能文件，还应有场景、观察结果及剩余问题。格式正确只是基本条件，不代表技能真的能引导 agent 正确工作。

编写技能时还需遵循当前环境的技能格式和写作规则。发布、安装、覆盖已有技能是独立操作，应按照你明确给出的范围执行；这个技能本身不会自动获得目录写入或推送权限。

与阅读本指南的区别

本指南是给开发者阅读的使用文档，没有创建新技能，因此不需要将每个章节当作待部署 SKILL.md。只有实际编写或修改技能时，才进入上述对照验证流程。

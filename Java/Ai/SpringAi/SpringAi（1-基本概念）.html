SpringAi（1-基本概念）

爱编程的小生2025/12/1大约 10 分钟JavaSpringAiAi

模型（Models）

人工智能模型是设计用来处理和生成信息的算法，通常模仿人类的认知功能，通过从大型数据集中学习模式和洞察力，这些模型可以做出预测，生成文本、图像或其他输出，增强各行各业的各种应用

下表根据它们的输入和输出类型对几种模型进行分类：

模型类型输入输出典型代表
LLM (大语言模型)文本文本GPT-4, Llama 3
VLM (视觉语言模型)文本+图像/视频文本Gemini 1.5 Pro, Claude 3.5 Sonnet
TTS / STT文本/音频音频/文本Whisper, ElevenLabs
VLA (视觉-语言-行动)视觉+语言物理控制指令Google RT-2

Spring AI 目前支持处理语言、图像和音频输入和输出的模型。它提供了一套统一的接口（如 ChatModel, ImageModel），让你可以在不同的 AI 提供商（如 OpenAI, Azure, Ollama, Bedrock）之间轻松切换，而无需修改大量代码。

多模态（Multimodality）

随着技术发展，多模态模型（如 GPT-4o, Gemini 1.5 Pro）正成为主流，这些模型不再局限于单一输入，而是能同时理解文本、图像甚至音频。例如，你可以上传一张图片并用语音询问关于图片的问题，模型能同时处理这些不同模态的信息。

  1. 大语言模型（LLM）

大语言模型（Large Language Model）：其输入和输出均只有文本这一个模态的数据。

LLM 之所以能基于单一的文本模态涌现出惊人的智能，一个核心原因在于，语言是传递信息效率最高的模态，能够以高度浓缩的形式承载复杂的逻辑与丰富的语义。所以相比其他单模态模型，LLM 具有最高的智能程度。

它不仅能够模仿人类的语言风格，更重要的是，在海量文本数据的训练下，目前已经发展出了记忆、理解、推理和生成能力。这些能力的结合，使得 LLM 成为当前生成式 AI 时代的基石，为后续更复杂的 AI 模型和应用提供了强大的技术底座。

  1. 多模态视觉-语言模型（VLM）

多模态视觉-语言模型（Vision-Language Model）：是一种能够同时理解图像（或视频）与文本，并在这两种模态之间建立深度关联的 AI 大模型

  1. 视觉-语言-行动模型（VLA）

视觉-语言-行动模型（Vision-Language-Action Model）：在视觉和语言的模态上，增加了“行动”（Action）这个至关重要的模态。

VLA 以 VLM 强大的理解能力为基础，将其对环境的感知，在同一个模型内转化为可以让实体智能体（如汽车、机器人）执行的电气控制指令。正是这一步，让 AI 拥有了与现实世界进行物理交互的能力。

模型参数（Parameters）

在调用模型时，除了提示词，还可以调整参数来控制输出风格：

  1. Temperature（温度）：控制输出的随机性。

  • 低（0.1 - 0.3）：结果更专注、确定，适合代码生成、事实问答。

  • 高（0.7 - 1.0+）：结果更有创造性、多样化，适合创意写作。

  1. Top-P：核采样参数，通过限制词汇选择范围来控制多样性。

标记（Tokens）

标记作为人工智能模型工作的基石。

  1. 输入时：模型将单词转换为标记。

  2. 输出时：它们将标记转换回单词。

在英语中，一个标记大致对应于一个单词的 75%。作为参考，莎士比亚的全部作品，总计约 900,000 个单词，翻译成大约 120 万个标记，标记 = 金钱。在托管的人工智能模型的背景下，你的费用由使用的标记数量决定，输入和输出都有助于总体标记计数。

计量关系：

  1. 英语：1 个 Token ≈ 0.75 个单词。

  2. 中文：1 个汉字 ≈ 1 到 2 个 Token（具体取决于模型使用的分词器）。

  3. 成本：在商业模型中，费用通常按 Token 使用量计算（输入 Token + 输出 Token）。

上下文窗口（Context Window）

每个模型都有 Token 限制（如 GPT-4 的 128k，Claude 3 的 200k+），这决定了模型在单次对话中能“记住”或处理多少信息（限制了单次 API 调用中处理的文本量），超出限制的文本会被截断或导致错误。

提示（Prompts）

提示作为基于语言的输入的基础，指导人工智能模型产生特定的输出。

  1. Zero-shot（零样本）：直接提问，不给示例。

例：“将这句话翻译成法语：...”

  1. Few-shot（少样本）：提供几个“问题-答案”对作为示例，引导模型模仿风格。

例：“将中文转为风格化诗句。例 1... 例 2... 请转换：...”

  1. Chain of Thought（CoT, 思维链）：要求模型“一步步思考”，能显著提高数学和逻辑推理的准确率。

例：“请逐步分析并给出结论。”

角色（Roles）

在与大模型交互（尤其是聊天模型）时，提示词通常包含多个消息片段，每个片段都有特定的角色：

  1. System（系统角色）：设定 AI 的“人设”、行为准则和边界。例如：“你是一个资深的 Java 架构师，只回答技术问题，回答要简洁。”

  2. User（用户角色）：用户的具体输入或问题。

  3. Assistant（助手角色）：AI 之前生成的回复。将这些历史回复带入新的请求中，模型才能拥有“记忆”。

提示词模板（Prompt Templates）

在 Spring AI 开发中，我们很少硬编码提示词。Prompt Template 允许开发者像使用 Java 字符串模板一样，通过占位符动态填充数据。

例如："请为 {role} 写一份关于 {topic} 的各种简历"。Spring AI 会在运行时将 {role} 替换为“软件工程师”，将 {topic} 替换为“Java”，生成最终的提示。

对话记忆（Chat Memory）

LLM 本身是无状态（Stateless）的。当你发送第二条消息时，它不知道你第一条消息说了什么。为了实现连续对话，应用程序必须维护对话历史。

机制：在每次请求时，将之前的 User 和 Assistant 消息打包，一同发送给模型。

短期记忆（Short-term Memory）

  1. 机制：通常基于 ChatMemory 接口，将当前会话的最近几轮对话存储在内存或 Redis 中。

  2. 管理：采用滑动窗口（只保留最近 N 条）或 总结压缩（将旧对话概括为一段摘要）来应对 Token 限制。

长期记忆（Long-term Memory）

  1. 机制：结合向量数据库持久化历史对话。

  2. 作用：当用户在几天甚至几月后再次提问时，系统通过向量搜索调取相关的历史上下文，使 AI 具备“长久记忆”。

结构化输出（Structured Output）

人工智能模型的原生输出通常是简单的字符串（java.lang.String）。即使你要求它“返回 JSON”，它返回的本质上仍然是一个包含 JSON 字符的字符串，且可能包含 Markdown 标记（如 json ... ）或格式错误。

为了解决这个问题，Spring AI 提供了输出解析器（Output Parsers），例如 BeanOutputParser。

工作流程：

  1. 开发者定义一个 Java 类（POJO）。

  2. Spring AI 自动生成该类的 JSON Schema。

  3. 将 Schema 注入到提示词中，指示 AI 严格按照该格式生成。

  4. Spring AI 接收 AI 的字符串响应，并自动将其反序列化为 Java 对象

工具调用（Tool Calling）

大型语言模型（LLM）在训练后被冻结，导致知识过时，并且它们无法访问或修改外部数据。

注意： 原有的“函数调用（Function Calling）”概念已逐渐演进并集成到更广泛的 Tool Calling 系统中。

LLM 无法直接访问实时数据或操作外部系统。工具调用机制让模型具备了“手脚”：

  1. 注册工具：在 Spring AI 中将 Java 方法注册为 Bean。

  2. 模型决策：模型发现需要实时数据（如查天气），会返回一个“调用请求”。

  3. 自动执行： Spring AI 拦截请求，自动调用本地 Java 方法，并将结果传回模型。

  4. 最终回复：模型根据工具返回的结果，组织成自然语言回答用户。

嵌入（Embeddings）

嵌入是文本、图像或视频的数值表示，捕捉输入之间的关系。

嵌入通过将文本、图像和视频转换为浮点数数组，称为向量，这些向量旨在捕捉文本、图像和视频的含义。

嵌入数组的长度称为向量的维度，通过计算两个文本的向量表示之间的数值距离，应用程序可以确定用于生成嵌入向量的对象之间的相似性。

向量数据库（Vector Databases）

为了支持 RAG 技术，我们需要一种专门存储高维向量的数据库。

  1. 传统数据库：通过关键词精确匹配（如 WHERE name = "John"）。

  2. 向量数据库：通过计算向量距离进行相似性搜索（如“查找与‘红色跑车’含义最接近的图片”）。

检索增强生成（Retrieval Augmented Generation）

大型语言模型存在两个主要缺陷：

  1. 知识过时：训练数据有截止日期。

  2. 数据隐私：无法访问企业内部的私有文档。

检索增强生成（RAG）通过在提示词中注入相关数据来解决这些问题，通过检索（Retrieval）相关信息并增强（Augmented）给模型进行生成（Generation）

RAG 流程（ETL 管道）：

  1. Extract（读取）：从 PDF、Word、网页等读取非结构化数据。

  2. Transform（分割）：将长文档分割（Split）成适合上下文窗口的小片段。

  3. Load（写入）：使用嵌入模型将片段转换为向量，并存入向量数据库。

  4. Retrieval（检索）：当用户提问时，将问题转换为向量，在数据库中查找最相似的片段。

  5. Generate（生成）：将“用户问题”+“检索到的相似片段”组合成提示词发送给 AI。

作为将非结构化数据加载到向量数据库的一部分，最重要的转换之一是将原始文档分割成较小的部分。将原始文档分割成较小部分的过程有两个重要步骤：

  1. 在分割文档时，要保留内容的语义边界。例如，对于包含段落和表格的文档，应避免在段落或表格的中间进行分割。对于代码，应避免在方法实现的中间分割代码。

  2. 将文档的部分进一步分割成大小仅为人工智能模型标记限制的一小部分的片段。

RAG 的下一个阶段是处理用户输入。当用户的问题需要由人工智能模型回答时，问题和所有“相似”的文档片段被放入发送到人工智能模型的提示中，这就是使用向量数据库的原因，它非常擅长找到相似的内容。

模型上下文协议（Model Context Protocol）

  1. 定义：一种开放协议，旨在让 AI 模型通过标准化的方式连接到各种数据源和工具（如 Google Drive、GitHub、Slack）。

  2. 作用：在 MCP 出现前，你需要为每个工具写集成代码；有了 MCP，只要数据源提供了 MCP Server，Spring AI 就能直接让模型读取其中的上下文，实现了真正的“插拔式”数据集成。

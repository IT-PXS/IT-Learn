Spring AI 1.0 学习路线

爱编程的小生2026/10/8大约 7 分钟

Spring AI 1.0 学习路线

这组笔记按由浅入深的顺序整理 Spring AI（Spring Boot 生态中的生成式 AI 应用开发框架）。主线是：模型调用 → 对话状态 → Prompt 工程 → 工具调用 → 向量检索 → RAG → 文档 ETL → MCP。

适用版本提示：目录名是“1.0”，但示例中出现了 spring-ai 1.1.2、Spring Boot 3.3.0 和 qwen3-max。实际学习或运行时应以项目的 BOM、JDK、Spring Boot 版本和模型供应商文档为准，避免把不同版本 API 混用。

如何阅读

建议按编号顺序阅读。每一章通常包含一篇 Markdown 主文档和同名目录中的截图/示例资源；主文档是知识梳理，图片主要用于流程和配置说明。

贯穿全程的核心模型

一次典型请求可以拆成下面几层：

用户请求
  → ChatClient / ChatModel
  → Prompt（系统指令 + 用户消息 + 记忆 + RAG 上下文）
  → 模型服务
  → 可能产生 Tool Call
  → 应用执行工具并回传结果
  → 结构化/流式响应

知识库场景则多一条离线链路：

文件 → DocumentReader → DocumentTransformer（清洗/分块/元数据）
     → EmbeddingModel → VectorStore
用户问题 → 查询改写/向量检索 → 上下文注入 Prompt → 模型回答

建议补充的知识点

下面这些内容在现有 9 章中较少涉及，建议作为“1.0 完成后的进阶清单”：

  1. 版本与依赖管理：Spring AI BOM、Spring Boot/JDK 兼容矩阵、模型供应商 starter 的选择、OpenAI 兼容接口的差异（鉴权、流式协议、工具调用格式）。
  2. 模型能力边界：ChatModel、EmbeddingModel、ImageModel、Audio/STT/TTS 的职责；上下文窗口、最大输出、温度与 Top-P 的联动；模型路由、降级和重试。
  3. 结构化输出落地：Java record/DTO 映射、JSON Schema、枚举和校验、解析失败重试，以及“结构化输出”和“工具调用”的边界。
  4. 记忆工程：按用户/租户/会话隔离，摘要记忆与窗口记忆，持久化清理策略，隐私删除，Token 预算，以及并发请求下的消息顺序。
  5. RAG 质量工程：文档去重、表格/代码/图片处理，分块大小与重叠率，混合检索（关键词 + 向量）、重排序（reranker）、父子文档、查询路由、引用来源和“无答案”策略。
  6. RAG 评估：召回率、MRR/NDCG、答案忠实度、相关性、覆盖率；建立小型评测集，比较参数和检索策略，防止只凭主观体验调优。
  7. Agent 与流程编排：工具循环、规划与执行、状态机、人工确认、最大步数、超时、幂等和失败补偿；区分“可控工作流”和“开放式 Agent”。
  8. 安全：API Key 使用环境变量/密钥管理服务，Prompt 注入与间接注入，工具最小权限，危险操作二次确认，租户隔离，输入/输出脱敏和审计。
  9. 可靠性与成本：超时、限流、熔断、重试退避、幂等、缓存、批量 Embedding、Token/费用统计、上下文压缩，以及流式响应中断处理。
  10. 可观测性：请求链路、Prompt/Completion Token、延迟、模型错误、Tool 调用、检索文档和用户反馈；注意日志中的密钥和个人信息脱敏。
  11. 多模态与异步：图片/音频输入输出，文件上传，异步任务、消息队列、WebFlux 背压和 SSE 断线重连。
  12. MCP 生产实践：工具发现与能力声明、资源/提示（Resources/Prompts）、鉴权、传输安全、连接生命周期、版本兼容、服务隔离和权限边界。STDIO 适合本地进程，SSE/HTTP 更适合远程服务，但应配合认证和网络访问控制。
  13. 部署与测试：使用 Ollama 等本地模型进行离线开发，Mock ChatModel/EmbeddingModel，工具调用契约测试，RAG 回归测试，容器化部署和配置分环境管理。

推荐的实践项目

按顺序做三个小项目，比单独阅读 API 更容易建立完整认识：

  1. 流式多轮助手：ChatClient + Redis ChatMemory + 会话隔离 + SSE 输出 + Token/错误日志。
  2. 可引用的企业知识库：PDF/Markdown ETL + Milvus + 混合检索/重排序 + 引用来源 + 无答案兜底。
  3. 受控工具型 Agent：天气/数据库查询等只读工具开始，加入参数校验、权限判断、人工确认、超时和审计，再通过 MCP 拆成独立工具服务。

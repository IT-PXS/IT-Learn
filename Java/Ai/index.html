AI 知识体系

Ai 目录用于沉淀生成式 AI 应用开发的公共知识；具体框架或厂商实现放在对应的子目录中。整理目标是做到：公共概念只讲一次，框架章节重点记录 API、配置和实践差异。

推荐目录结构

Ai/
├─ README.md                         # 总目录、学习路线和术语入口
├─ 00-公共基础/                      # 与具体框架无关的知识
│  ├─ 01-模型与推理.md
│  ├─ 02-Token与上下文.md
│  ├─ 03-Prompt工程.md
│  ├─ 04-结构化输出.md
│  ├─ 05-Embedding与向量.md
│  ├─ 06-RAG基础.md
│  ├─ 07-工具调用与Agent.md
│  ├─ 08-MCP.md
│  ├─ 09-评估、可观测性与安全.md
│  └─ 10-成本、性能与部署.md
├─ SpringAi（1.0）/                  # Spring AI 框架实现
├─ SpringAiAlibaba/                  # 阿里云/百炼相关实现
├─ Langchain4j/                      # LangChain4j 实现
└─ Ai Agent/                         # Agent 专题或案例

目录编号可以按实际维护习惯调整；关键是固定“公共知识”和“框架知识”的边界。

内容边界

放入 00-公共基础

放概念、原理、设计方法和评估方法，例如模型类型、上下文窗口、采样参数、Prompt 设计、Embedding、向量相似度、RAG 流程、Agent 模式、MCP 概念、安全和可观测性。这些内容不应绑定某个 Java 类名或某个供应商配置。

放入框架目录

放依赖和版本、自动配置、核心 API、代码示例、框架特有的 Advisor/Memory/VectorStore、异常处理、测试方式，以及同一能力在不同框架中的实现差异。

放入厂商目录

放模型名称、Endpoint、鉴权、限流、计费、模型能力差异、兼容模式限制和厂商特有功能。通用的模型调用原理仍回到公共基础目录。

放入 Agent 专题

放工作流、状态机、ReAct、Plan-and-Execute、多 Agent、人工确认、工具权限和失败补偿。Agent 的通用设计放公共层，具体 Spring AI/LangChain4j 代码放框架层。

现有内容的迁移建议

当前内容建议处理
Ai Agent.md拆出公共的 Agent 定义、记忆、RAG；框架实现分别回填对应框架目录
Agent工作流.md保留 Agent 的流程、检索和编排概念；工程实现通过链接引出
Agent工程实践.md集中记录状态、上下文、工具安全、失败恢复、评估和可观测性
SpringAi（1.0）/SpringAi（1-基本概念）.md将模型、Token、Prompt、Embedding、RAG、MCP 等通用部分拆到 00-公共基础；保留 Spring AI 的接口映射
SpringAi（1.0） 其余文件保留框架目录，集中记录 Spring AI 的实现方式
SpringAiAlibaba保留厂商目录，补充模型能力、兼容 API 和配置差异
Langchain4j按同一公共知识索引补充框架实现
迁移时建议先复制、建立新链接并检查站点构建，再删除旧内容，避免一次性移动造成链接和图片路径失效。

推荐学习顺序

  1. 公共基础：模型、Token、Prompt、结构化输出。
  2. 知识增强：Embedding、向量库、RAG、文档 ETL。
  3. 交互能力：Tool、Agent、工作流和 MCP。
  4. 工程能力：记忆、评估、可观测性、安全、成本、性能和部署。
  5. 框架实践：Spring AI → Spring AI Alibaba → LangChain4j，对比同一能力的 API 和工程取舍。

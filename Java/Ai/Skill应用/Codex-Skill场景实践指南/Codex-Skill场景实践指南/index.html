Codex Skill 场景实践指南

这套指南面向第一次使用 Skill 的开发者，以 ATM 前端为示例。项目路径和例子需要根据实际项目替换；文档中的重复列表、状态管理等场景不是已经确认的 ATM 问题。本指南默认 Skill 已经配置好，重点记录如何选择、调用和验证 Skill。通用背景和两套指南的关系见上级目录的 Skill 应用总览。

第一次阅读怎么走

  1. 先读 00 快速上手，用一个小任务体验输入、执行、验证。
  2. 根据下方导航挑一份场景文档，不必从头到尾执行所有流程。
  3. 想完整练习时，读 09 端到端实战。
  4. 不确定怎样组合技能或遇到卡点时，查 10 技能组合与常见卡点。

每次工作只需说清楚：项目在哪里、要改善什么、允许修改什么、如何证明完成。Skill 帮助规范执行过程，但不能替你决定业务规则，也不能代替运行验证。

已核实的 ATM 背景

2026-09-20 查看 D:/item/front/atm/package.json 和前端入口后确认：ATM 前端位于 D:/item/front/atm，使用 React 19、TypeScript 5、Vite 7、React Router 7、Tailwind CSS 3，声明包管理器为 Bun 1.3.10。这里列的是依赖声明的主版本，实际安装版本需要核对锁文件。

已有 dev、lint、build 等脚本，未声明 test 脚本。这不等于已经证明仓库完全没有测试；开始测试工作前仍需查找测试文件、配置和依赖。不要把 Vue、Next.js 或 Vitest 专用规则直接当成此项目已经具备的能力。

先理解关系

这些 Skill 不是互斥的“需求类、架构类”插件，而是可以按目标组合的工作方法。同一个 Skill 可以出现在多个场景里。本文按你要完成的工作组织文件，通用方法通过链接复用，不把同一套说明复制到每个场景。

与 Superpowers 的配合

Codex Skill 更适合把问题澄清成规格、判断架构改进机会、整理任务边界和治理项目知识；Superpowers 更适合把已确认的工作按设计、计划、实施、测试、审查和收尾串起来。两套 Skill 可以按任务需要组合，不需要重复执行相同阶段。

当前需要先使用后续可组合
想法还不清楚grill-me、grill-with-docsbrainstorming、to-spec
已有共识，需要可执行任务to-spec、to-ticketswriting-plans、executing-plans
具体故障需要定位diagnosing-bugssystematic-debugging、tdd
已有改动需要检查code-reviewrequesting-code-review、verification-before-completion

选择 Skill 时先看当前问题的产物是什么：讨论结论、规格、任务清单、架构报告、修复代码或审查结果。产物不明确时，先回到 00 快速上手 澄清输入和完成标准。

三条常见路径

  • 新需求：澄清 → 规格（按需）→ 拆任务（按需）→ 实施与测试 → 审查。
  • 架构改进：调查报告 → 选定问题并澄清约束 → 设计方案 → 实施与测试 → 审查。
  • Bug 修复：复现 → 根因验证 → 最小修复与回归 → 按需审查；有证据表明存在架构障碍时，再单独规划重构。

初始化是项目级准备，不是每条路径都重新执行一次。小而明确的工作可以省略规格或拆任务；读到某个 Skill 名称不意味着必须调用它。

使用原则

  • 把初始化、测试与审查独立出来，供所有开发场景使用。
  • 将 grill 系列放在“想法、需求与方案澄清”，覆盖产品与技术决策。
  • 区分全项目规范体检与指定代码差异审查；自动格式化规则由工具检查。
  • 按当前安装版本修正 tdd：先确认测试接口，按一个失败测试、一个最小实现推进；该版本将重构安排在后续审查阶段，不是每轮自动重构。
  • 保留原指南的可复制指令和操作示例，并用跨文档链接连接各阶段。

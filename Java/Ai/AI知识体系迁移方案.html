AI 知识体系迁移方案

1. 文档目的

本文用于指导 Java/Ai 目录后续的分阶段整理。本阶段只建立迁移方案，不直接移动、删除或重写现有知识文档。

迁移目标是建立清晰的知识主线：公共概念只维护一份，Agent 专题负责流程和工程治理，具体框架目录负责 API、配置和实现差异，厂商目录负责模型和平台差异。

迁移过程中采用“先盘点、再复制和建链、最后清理”的方式，避免一次性移动导致内容缺失、链接断裂、图片路径失效或知识边界混乱。

2. 当前内容盘点

2.1 公共入口

Java/Ai/README.md 已经定义了公共基础、Agent 专题、Spring AI、Spring AI Alibaba 和 LangChain4j 的边界，也给出了迁移建议。后续整理应以该边界为总规则，并将 README 逐步完善为目录索引和学习路线入口。

2.2 Agent 相关文档

当前文件当前内容后续职责

Ai Agent.mdAgent、Prompt、结构化输出、Tool、MCP、记忆、RAG拆分公共基础；不作为长期大杂烩文档
Agent工作流.md意图、查询改写、召回、重排、Agent Loop、编排模式Agent 工作流和编排模式
Agent工程实践.md状态、上下文、Harness、Skill、安全、恢复、评估、可观测性Agent 生产工程实践

2.3 Spring AI 文档

当前 Spring AI 已有一条较完整的学习路线：

模型调用 → 会话记忆 → Prompt → Tool → 向量检索 → RAG → ETL → MCP

其中 SpringAi（1-基本概念）.md 同时包含 AI 公共概念和 Spring AI 映射，存在明显的跨层内容：

当前章节主要归属Spring AI 目录应保留的内容
模型、多模态、参数、Token、上下文窗口公共基础ChatModel、ImageModel 等接口和参数配置

Embedding、向量库公共基础EmbeddingModel、VectorStore、Milvus 配置
RAG公共基础Advisor、检索增强组件和 Spring AI 配置
MCP公共基础MCP Client/Server、STDIO、HTTP 配置和示例

此外，SpringAi/README.md 与 SpringAi（2-基本使用）.md 的 Spring Boot 示例版本目前不一致，后续应集中维护版本和兼容矩阵。

4. 内容归属规则

4.1 00-公共基础

放跨框架、跨供应商成立的概念、原理、设计方法和评估方法，例如：

  • 模型类型、采样参数、Token 和上下文窗口；
  • Prompt、消息角色、结构化输出和结果校验；
  • Embedding、向量相似度、分块、召回、重排和 RAG；
  • Tool Calling、MCP 的协议角色和安全边界；
  • 记忆、上下文工程、评估、可观测性、安全、成本和可靠性。

公共文章不绑定 Java 类名、Starter、Advisor、厂商 Endpoint 或具体版本。

4.2 Agent

放面向任务执行的系统设计：

  • Agent、Workflow、Agent Loop 的关系；
  • 意图识别、路由、规划、检索、工具执行和结果验证；
  • ReAct、Plan-and-Execute、Reflexion、Critic、Multi-Agent 和人工确认；
  • 状态机、检查点、恢复、预算、停止条件、权限、审计和线上评估。

Agent 文档可以引用公共基础，但不复制公共概念的完整解释。

4.3 SpringAi

放 Spring AI 的依赖、版本、自动配置、核心 API、代码示例、Advisor、Memory、VectorStore、ETL、MCP 组件、测试方式和异常处理。

每篇框架文章都应回答：

  1. Spring AI 用什么抽象承载该能力？
  2. 依赖和配置如何写？
  3. 最小代码示例是什么？
  4. 与公共概念相比有哪些实现差异或限制？

4.4 厂商目录

放模型名称、Endpoint、鉴权、限流、计费、模型能力差异、兼容 API 限制和厂商特有功能。通用模型调用原理仍然回到公共基础。

RAG 建库、分块、召回、重排、引用00-公共基础/07-RAG基础.md

5.2 Agent核心关系.md

保留为 Agent 目录入口。只保留 Prompt、Context、Harness、Loop 的层次关系、边界和阅读导航；详细工具、RAG、记忆和生产治理内容通过链接引出。

5.3 Agent工作流.md

保留完整任务流程、检索链路和编排模式。检索的通用原理链接到公共 RAG 文章，状态持久化和安全治理链接到工程实践文章。

5.4 Agent工程实践.md

保留状态、上下文工程、Harness、Skill、失败恢复、工具安全、评估和可观测性。具体 Spring AI API 不放在此文档中。

5.5 SpringAi（1-基本概念）.md

不直接删除。先建立章节级映射：

  1. 复制公共概念到目标公共文章，并保留来源记录；
  2. 将 Spring AI 专属内容回填到对应 Spring AI 实现文章；
  3. 通过链接替代重复理论；
  4. 最后决定将原文改成 Spring AI 能力总览，或在链接稳定后归档。

5.6 Spring AI 其余文章

原则上保留在 Spring AI 目录，重点检查是否混入公共理论：

  • （2-基本使用）：保留依赖、配置、ChatModel、ChatClient、调用方式和 Advisor；
  • （3-会话记忆）：保留 ChatMemory、Memory Advisor 和存储实现；
  • （4-Prompt提示词）：保留 Prompt API、模板渲染和 Spring AI 示例；
  • （5-Tool工具调用）：保留注解、参数、上下文和 Spring AI 执行流程；
  • （6-向量存储与检索）：保留 EmbeddingModel、VectorStore 和具体向量库；
  • （7-RAG加强检索）：保留 Advisor、查询转换和检索增强组件；
  • （8-ETL文档读取转换写入）：保留 Reader、Transformer、Splitter 和 Writer；
  • （9-MCP）：保留 Spring AI MCP 客户端、服务端和传输配置。

6. 分阶段迁移计划

阶段 0：建立基线

目标是冻结现状并建立可追踪清单：

  • 记录所有 Markdown、图片、代码示例和内部链接；
  • 为每篇文章建立“当前职责、目标位置、待拆章节、外部链接”清单；
  • 确认当前站点构建方式和校验命令；
  • 记录 Spring AI、Spring Boot、JDK 和模型供应商版本。

本阶段只新增清单或方案文档，不移动原文。

阶段 1：先建公共基础骨架

先创建目标目录和文章标题、元数据、章节骨架，再从现有文档复制内容。此阶段不删除旧章节，公共文章与旧文章并存。

阶段 2：整理 Agent 专题

将四篇 Agent 文档按“概念关系 → 工作流 → 工程实践”建立链接和边界，先解决重复和入口问题，再决定 Ai Agent.md 的归档方式。

阶段 3：整理 Spring AI 基本概念

拆分 SpringAi（1-基本概念）.md：公共内容进入 00-公共基础，Spring AI API 内容进入对应章节。完成后更新 Spring AI README 的学习路线。

阶段 4：补充框架实现索引

在每篇公共文章末尾增加“相关框架实现”链接；在每篇框架文章开头注明依赖的公共基础文章，避免复制理论。

阶段 5：清理旧内容

只有在以下条件全部满足后，才删除或重命名旧文档：

  • 内容已迁移并逐段核对；
  • 图片、代码和链接均已验证；
  • 站点构建通过；
  • README、目录索引和交叉引用已更新；
  • Git diff 可以清楚说明删除内容对应的新位置。

7. 每阶段的验收标准

每次迁移至少检查以下项目：

  • Markdown 标题层级连续，不能出现无归属的标题；
  • 内部链接可以解析，空格和中文文件名链接可正常访问；
  • 图片相对路径仍然有效；
  • 公共文章不出现框架类名、Starter 或厂商配置；
  • 框架文章不重复大段公共理论；
  • 示例中的版本、依赖和 API 彼此一致；
  • 关键结论、代码示例和引用没有因拆分丢失；
  • VuePress 或当前站点构建成功；
  • Git diff 中没有无意删除或改写。

8. 回滚和变更控制

迁移以小批次进行，每个阶段或主题单独提交。优先采用复制和建立链接，确认新结构稳定后再删除旧内容。

每次提交的说明应包含：

  • 本次迁移的源文件和目标文件；
  • 搬迁、拆分、重写和删除的范围；
  • 链接、图片和站点构建的验证结果；
  • 尚未处理的重复内容或版本问题。

如果构建、链接或内容核对失败，应恢复到上一阶段，不继续叠加迁移范围。

9. 推荐阅读路线

整理完成后，读者应按以下路径学习：

公共基础：模型 → Token/Context → Prompt → 结构化输出
    ↓
知识增强：Embedding/向量 → RAG → ETL → 引用与评估
    ↓
交互能力：Tool → MCP → 记忆
    ↓
Agent 专题：核心关系 → 工作流 → 工程实践
    ↓
框架实践：Spring AI → Spring AI Alibaba → LangChain4j

这条路线既能先理解公共概念，也能在需要时进入具体框架实现，避免把 Spring AI 的 API 笔记误当成 AI 基础知识。

10. 当前结论

本方案确定三条不可混淆的边界：

  1. 公共基础回答“是什么、为什么、怎么设计”；
  2. Agent 专题回答“如何围绕目标组织流程并稳定执行”；
  3. 框架和厂商目录回答“在某个技术栈或平台中如何实现”。

后续每次迁移都应先将内容归类到这三层之一，再决定目标文件和链接关系，不直接在旧文档之间复制粘贴。

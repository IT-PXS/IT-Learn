本文沿用上一篇文章的 OpenAI 兼容模型配置和基础依赖。Spring AI 和 Spring Boot 的版本由 BOM 和依赖管理统一提供：

Prompt 的基本概念

Prompt 是什么

Prompt 是发送给模型的一组消息和指令，不只是用户输入，还可以包含系统指令、对话历史、示例和输出约束。模型不会自动记住上一次请求的内容，应用需要在每次请求中重新提供需要使用的上下文。

一个可维护的 Prompt 通常包含：

角色：模型应该以什么身份工作
任务：需要完成什么事情
输入：需要处理的原始内容
约束：必须遵守和禁止做什么
输出：结果的格式、字段和语言
示例：输入与期望输出的参考样例

Prompt 与 Message、ChatModel 的关系

Spring AI 用下面的链路表示一次模型请求：

Message → Prompt → ChatModel → ChatResponse
  • Message：一条带有角色和内容的消息，例如 SystemMessage、UserMessage 或 AssistantMessage。
  • Prompt：一次请求的消息集合，可以包含系统指令、用户问题和模型调用参数。
  • ChatModel：直接调用模型的底层接口。
  • ChatResponse：模型返回的完整结果，可以读取文本、元数据和 Token 使用信息。

模板只负责在调用前生成消息文本，不保存会话记忆，也不负责权限控制。需要历史上下文时，应配合 Chat Memory Advisor 或显式组装消息。

Prompt 的基本组成

SystemMessage：系统指令

SystemMessage 用于设置模型的角色、行为规则、输出要求和回答边界。它通常由应用程序生成，不应该直接由用户覆盖。

UserMessage：用户输入

UserMessage 用于传递当前问题、任务和待处理内容。用户输入可能包含提示注入内容，因此必须在服务端进行长度限制、权限检查和内容校验。

AssistantMessage：历史回复

AssistantMessage 表示模型已经生成的回复。在多轮对话中，应用可以将历史用户消息和助手消息一起放入下一次 Prompt。

工具相关消息

工具相关消息表示模型请求调用工具或工具执行后的结果，不能简单理解为普通用户消息。权限校验和工具调用次数限制仍然由应用程序负责。

Prompt 的设计方法

明确任务和输出

直接说明动作、对象和结果格式。例如：

用 200 字总结人工智能在医疗领域的三个应用，并按“应用—价值”格式列出。

它比“谈谈人工智能”包含更多可执行信息，更容易得到稳定结果。复杂任务可以拆成“提取事实 → 判断类别 → 生成答案”等步骤。

区分指令与输入

把用户提供的内容放在明确的分隔区域中：

请将 <input> 中的文本翻译为法语，并保留专业术语。

<input>
The patient's MRI showed a lesion in the left temporal lobe.
Clinical diagnosis: probable glioma.
</input>

分隔符只能帮助模型理解边界，不能代替服务端的权限校验、输入过滤和敏感数据保护。

提供示例

少量高质量的输入—输出示例可以约束格式、语气和边界。示例要和真实任务保持一致，避免示例本身引入互相矛盾的规则。示例中的事实、字段和评分规则也需要经过业务人员审核。

指定输出格式

明确要求模型输出 JSON、Markdown、表格或固定字段。格式要求应同时说明字段含义、必填项和异常情况。如果结果要被程序解析，还需要在服务端校验结构和字段值，不能只依赖 Prompt 保证格式正确。

引用依据和处理不确定性

可以要求模型只依据提供的资料回答，资料不足时返回“无法根据现有资料判断”，并引用输入中的依据。角色描述应与任务相关、范围明确；它用于减少歧义，不是权限控制机制。需要事实准确时，仍要在模型输出后使用数据库、规则或其他可信来源进行校验。

Spring AI 的 Prompt API

Prompt 模板的处理流程可以表示为：

模板字符串 + 变量
        ↓
TemplateRenderer
        ↓
Prompt / Message
        ↓
ChatModel 或 ChatClient

这几个 API 都用于模板渲染，但职责不同：

API作用常见结果不负责的事情
PromptTemplate渲染普通用户消息或通用 PromptPrompt、Message 或字符串不调用模型、不保存记忆
SystemPromptTemplate渲染系统消息SystemMessage不执行权限控制
StTemplateRenderer替换模板变量和分隔符渲染后的字符串不验证变量的业务含义

Spring AI 1.1.2 的 PromptTemplate 默认使用 StTemplateRenderer，模板变量默认使用 {变量名} 表示。需要处理 JSON 等包含花括号的内容时，可以更换变量分隔符。

PromptTemplate

PromptTemplate 使用占位符定义可复用的消息。调用 create(Map) 可以生成完整的 Prompt：

@RestController
public class PromptController {

    private final ChatClient chatClient;

    public PromptController(ChatClient chatClient) {
        this.chatClient = chatClient;
    }

    @GetMapping("/prompt")
    public String prompt(@RequestParam("topic") String topic) {
        PromptTemplate template = new PromptTemplate(
                "请给我讲一个关于 {topic} 主题的故事，控制在 300 字以内。"
        );
        Prompt prompt = template.create(Map.of("topic", topic));

        return chatClient.prompt(prompt)
                .call()
                .content();
    }
}

create() 负责根据变量生成 Prompt，ChatClient 负责发送请求并读取响应。模板变量应来自经过校验的业务数据；如果变量内容来自用户，仍要执行长度限制和业务校验。

需要直接生成消息时，可以使用 createMessage()：

PromptTemplate template = new PromptTemplate(
        "请介绍 {topic}，并列出三个关键概念。"
);
Message userMessage = template.createMessage(
        Map.of("topic", "Spring AI")
);

ChatResponse response = chatModel.call(new Prompt(userMessage));
String text = response.getResult().getOutput().getText();

SystemPromptTemplate

SystemPromptTemplate 专门用于生成 SystemMessage。构造多消息 Prompt 时，应先放系统消息，再放用户消息：

@GetMapping("/prompt/system")
public String promptWithSystem(@RequestParam("topic") String topic,
                               @RequestParam("voice") String voice) {
    SystemPromptTemplate systemTemplate = new SystemPromptTemplate("""
            你是一名中国古典文学讲解员。
            请使用 {voice} 的语言风格回答，只回答与故事主题有关的内容。
            """);
    Message systemMessage = systemTemplate.createMessage(
            Map.of("voice", voice)
    );

    PromptTemplate userTemplate = new PromptTemplate(
            "请讲一个关于 {topic} 的故事，并列出故事的寓意。"
    );
    Message userMessage = userTemplate.createMessage(
            Map.of("topic", topic)
    );

    Prompt prompt = new Prompt(List.of(systemMessage, userMessage));
    ChatResponse response = chatModel.call(prompt);
    return response.getResult().getOutput().getText();
}

系统消息不是安全边界，服务端仍应进行鉴权、输入校验和输出检查。voice 和 topic 只是模板变量，不能让用户借此修改应用的权限规则。

自定义模板渲染器

默认 {} 分隔符可能与业务文本中的花括号冲突，可以用 StTemplateRenderer 修改分隔符：

PromptTemplate template = PromptTemplate.builder()
        .renderer(StTemplateRenderer.builder()
                .startDelimiterToken('<')
                .endDelimiterToken('>')
                .build())
        .template("列出 5 部由 <composer> 创作配乐的电影。")
        .build();

String prompt = template.render(
        Map.of("composer", "John Williams")
);

如果模板变量来自用户，优先使用结构化参数和白名单校验，不要把用户输入拼接成新的系统指令或模板语法。自定义分隔符只能解决语法冲突，不能解决提示注入问题。

ChatClient 中的模板写法

业务代码中更常见的是直接在 ChatClient 的 user() 或 system() 中使用模板变量：

@GetMapping("/prompt/client")
public String promptWithChatClient(@RequestParam("topic") String topic) {
    return chatClient.prompt()
            .system("你是一名 Java 技术助手，回答要简洁。")
            .user(user -> user
                    .text("请介绍 {topic}，并列出三个关键概念。")
                    .param("topic", topic))
            .call()
            .content();
}

ChatClient 内部仍然使用 PromptTemplate 处理变量。通过 .templateRenderer() 配置的渲染器，只影响当前 ChatClient 链中直接定义的用户消息和系统消息，不会改变已经创建的 PromptTemplate 或 Advisor 内部模板。

Prompt 与会话记忆

模板和会话记忆的职责

模板负责生成稳定的指令和当前请求的变量，Chat Memory 负责保存和读取历史消息，两者职责不同：

PromptTemplate：生成当前请求的指令
ChatMemory：保存和读取历史消息
ChatMemoryAdvisor：把历史消息加入当前请求

使用记忆 Advisor 时，不要再手动把同一份历史拼接到 Prompt，否则可能重复注入上下文。每次请求还要传入正确的 conversationId，确保不同用户和不同会话互相隔离。

使用 MessageChatMemoryAdvisor

使用 MessageChatMemoryAdvisor 自动管理历史消息：

@Bean
public ChatClient chatClient(ChatModel chatModel, ChatMemory chatMemory) {
    return ChatClient.builder(chatModel)
            .defaultSystem("你是一名 Java 技术助手，只根据对话内容回答问题。")
            .defaultAdvisors(
                    MessageChatMemoryAdvisor.builder(chatMemory).build(),
                    new SimpleLoggerAdvisor())
            .build();
}

调用时只传入当前用户问题，并通过 ChatMemory.CONVERSATION_ID 指定会话：

@GetMapping("/prompt/memory")
public String promptWithMemory(@RequestParam("msg") String msg,
                               @RequestParam("conversationId") String conversationId) {
    return chatClient.prompt()
            .user(msg)
            .advisors(a -> a.param(
                    ChatMemory.CONVERSATION_ID, conversationId))
            .call()
            .content();
}

MessageChatMemoryAdvisor 会读取历史消息，将其加入当前 Prompt，并在响应完成后保存本轮消息。调用方不需要再次手动保存用户消息和助手回复。

如果希望逐段展示结果，可以使用流式调用：

@GetMapping("/prompt/memory/stream")
public Flux<String> promptWithMemoryStream(
        @RequestParam("msg") String msg,
        @RequestParam("conversationId") String conversationId) {
    return chatClient.prompt()
            .user(msg)
            .advisors(a -> a.param(
                    ChatMemory.CONVERSATION_ID, conversationId))
            .stream()
            .content();
}

conversationId 只负责定位上下文，不等于权限校验。应用仍需要确认当前用户有权访问这个会话。

PromptChatMemoryAdvisor 的兼容说明

PromptChatMemoryAdvisor 会把历史消息整理成文本，再追加到 System Prompt。Spring AI 1.1.2 仍支持 systemPromptTemplate()，但该类自 1.1.3 起被弃用，后续版本的模板行为也有变化。

因此，新项目优先使用 MessageChatMemoryAdvisor；只有在维护 1.1.2 代码或确实需要旧的文本拼接方式时，才考虑使用 PromptChatMemoryAdvisor。升级时应检查官方迁移说明，不能直接把旧示例复制到新版本。

提示词安全

提示词安全是应用边界控制的一部分，不能只依靠一段系统 Prompt。

提示注入和越狱

用户输入可能包含“忽略之前指令”等内容。应用应将外部输入与系统指令分开传入，限制用户输入能影响的范围，并结合内容审核、权限检查和人工复核。分隔符和拒答规则不能替代接口鉴权。

敏感数据和资源消耗

不要把不必要的密钥、个人信息或内部提示词放入请求。对输入长度、历史消息数量和生成长度设置上限，避免敏感数据泄露、成本失控或拒绝服务。

数据泄露和模型欺骗

对敏感问题可以设置固定回复，并在业务层过滤不应暴露的字段。对于需要事实准确性的任务，要求模型引用输入中的依据、标记不确定信息，并在返回后使用数据库、规则或其他可信来源进行校验。

拒绝服务

限制单次输入和输出的 Token 数量，限制递归调用、重复请求和工具调用次数。复杂度检测、超时和限流应在应用层完成，不能只依赖 Prompt 中的“不要执行复杂请求”。

使用案例：Java 面试官

下面沿用 Java 高级工程师面试的场景，把角色、任务、评分规则、输出格式和对话示例组合成一份系统 Prompt，再通过会话记忆保持连续问答。

编写系统 Prompt

面试官需要知道“问什么、如何评价、何时结束”，仅设置角色还不够。下面定义初始分数和评分标准，并用两组对话示例展示回答不足与回答良好时的处理方式：

public final class InterviewPrompts {

    private InterviewPrompts() {
    }

    public static final String SYSTEM = """
            ## 角色与目标
            你是一家科技公司的技术主管，正在进行 Java 高级工程师模拟面试。
            只以面试官身份回复，不代替候选人回答。
            根据候选人的回答给出评价，再提出一个后续问题。

            ## 面试流程
            - 开始时问好，请候选人介绍工作经历，不对开场问候评分。
            - 围绕 Java 基础、并发、JVM、Spring 和项目实践进行提问。
            - 根据回答调整问题难度，一次只提出一个问题。
            - 说明回答的正确之处和不足，再给出本轮分数变化。
            - 不编造候选人的经历；信息不足时先追问。
            - 对无关请求回复“请继续面试”，分数保持不变。
            - 下面的示例只是格式参考，不能当作当前候选人的经历。

            ## 评分规则
            - 初始总分为 50 分，总分范围为 0 到 100 分。
            - 本轮总分 = 上轮总分 + 本轮分数变化，超出范围时取边界值。
            - -10：完全错误或答非所问。
            - -5：回答不完整，存在明显缺陷。
            - 0：基本正确，但缺乏解释和深度。
            - +5：回答清楚，展示扎实的基础。
            - +10：回答深入，能结合实际问题说明原理和取舍。
            - 总分不超过 30 分时结束面试；达到 80 分时判定通过。
            - 面试结束后不再提出新问题；候选人主动结束时给出总结。

            ## 输出格式
            （面试官表情）评价或引导语
            评分：本轮分数变化
            总分：当前总分/100
            下一题：一个问题

            结束面试时，将“下一题”替换为“结果：面试结论与学习建议”。

            ## 示例一：回答不足
            User: 我来面试 Java 高级工程师职位。
            Assistant:
            （微笑）你好，请简单介绍你的工作经历和负责过的项目。
            评分：0
            总分：50/100
            下一题：你最近负责的项目是什么？

            User: 我做过很多项目，具体用了什么技术记不清了。
            Assistant:
            （认真）请补充一个项目中的具体职责和技术方案。
            评分：-5
            总分：45/100
            下一题：请选择一个项目，说明其中使用 Spring 的方式。

            User: Spring 就是数据库，负责把 Java 对象存起来。
            Assistant:
            （认真）Spring 是应用开发框架，不能等同于数据库。这个回答存在概念错误。
            评分：-10
            总分：35/100
            下一题：Spring 的 IoC 容器主要解决什么问题？

            User: IoC 就是控制线程先后执行，我不了解其他内容。
            Assistant:
            （认真）IoC 主要涉及对象的创建、配置和依赖管理。
            评分：-10
            总分：25/100
            结果：本次模拟面试未通过，建议先复习 Spring IoC 和依赖注入。

            ## 示例二：回答良好
            User: 我来面试 Java 高级工程师职位。
            Assistant:
            （微笑）你好，请简单介绍你的工作经历和负责过的项目。
            评分：0
            总分：50/100
            下一题：你最近负责的项目是什么？

            User: 我有五年 Java 开发经验，负责订单服务的设计和微服务改造，
            用唯一请求号和数据库唯一约束避免订单重复创建，并为下游调用设置超时。
            Assistant:
            （点头）你说明了具体职责，并给出幂等和超时处理措施。
            评分：+10
            总分：60/100
            下一题：如果订单已经提交，但客户端超时重试，如何返回一致的结果？

            User: 重试时使用相同请求号，先查询已保存的处理结果；
            并发请求依靠唯一约束避免重复写入，区分处理中和已完成状态。
            Assistant:
            （点头）你考虑了结果复用、并发竞争和状态区分。
            评分：+10
            总分：70/100
            下一题：创建订单后发送消息失败，如何保证下游最终收到消息？

            User: 在同一数据库事务中写订单和本地消息表，由后台任务重试投递；
            消费端仍需幂等，避免重复消费。
            Assistant:
            （点头）你说明了本地事务、补偿投递和消费幂等之间的关系。
            评分：+10
            总分：80/100
            结果：通过本次模拟面试，建议继续学习消息积压处理和故障恢复。
            """;
}

角色、流程、评分规则、输出格式和对话示例各自承担不同职责。示例必须和评分规则一致，不能在未达到结束条件时提前宣布通过。示例中的历史分数只是给模型参考，不能当作可信状态来源。

配置 ChatClient 和会话记忆

将系统 Prompt 注册为默认系统消息，并使用 Chat Memory 保存同一场面试的问答。此配置替换前面演示用的配置：

@Configuration
public class InterviewConfiguration {

    @Bean
    public ChatMemory interviewChatMemory(JdbcChatMemoryRepository repository) {
        return MessageWindowChatMemory.builder()
                .chatMemoryRepository(repository)
                // 限制消息条数，不是限制面试轮数或 Token 数
                .maxMessages(20)
                .build();
    }

    @Bean
    public ChatClient interviewChatClient(
            ChatModel chatModel,
            @Qualifier("interviewChatMemory") ChatMemory chatMemory) {
        return ChatClient.builder(chatModel)
                .defaultSystem(InterviewPrompts.SYSTEM)
                .defaultAdvisors(
                        MessageChatMemoryAdvisor.builder(chatMemory).build(),
                        new SimpleLoggerAdvisor())
                .build();
    }
}

JDBC 负责保存当前记忆窗口，MessageWindowChatMemory 负责限制上下文窗口。旧消息超出窗口后会被淘汰；如果需要完整的面试记录，应另外保存原始消息和业务状态。

接收候选人回答

每次请求只传入本轮回答，历史问答由记忆 Advisor 加入：

@RestController
public class InterviewController {

    private final ChatClient chatClient;

    public InterviewController(
            @Qualifier("interviewChatClient") ChatClient chatClient) {
        this.chatClient = chatClient;
    }

    @GetMapping("/interview")
    public String interview(@RequestParam("msg") String msg,
                            @RequestParam("conversationId") String conversationId) {
        return chatClient.prompt()
                .user(msg)
                // 同一次面试持续使用同一个 ID
                .advisors(a -> a.param(
                        ChatMemory.CONVERSATION_ID, conversationId))
                .call()
                .content();
    }
}

开始面试时传入“我来面试 Java 高级工程师职位”，之后继续使用相同的 conversationId 提交回答。重新开始面试时使用新的 ID，就不会带入上一场面试的问答和分数。会话 ID 只负责定位上下文，应用仍需校验当前用户是否有权访问该会话。

本例让模型根据历史回复推算总分，用于演示 Prompt 和会话记忆如何配合。它不保证分数计算始终正确；历史超出窗口后，模型可能失去早期评分信息。如果需要可靠的累计分数和面试状态，应由业务代码保存并计算，再把当前状态提供给模型。模型只负责生成评价、下一道题和解释性文字，服务端应校验分数变化、结束状态和输出格式。
